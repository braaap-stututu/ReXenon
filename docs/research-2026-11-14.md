# ReXenon research report

All gains below are static counts or labelled estimates. No whole-game runtime A/B was run, because the game and the FX test PC were off-limits.

## 1. Verdict

ReXenon can be a clear win on correctness and on zero-config setup for new games. On speed it will be modest.

- **Correctness:** this is the strongest case. Several silent-miscompile classes are confirmed:
  - Branches into the middle of another function become a bare `return;`: 1 site in FM2, about 130 `// ERROR` lines (74 distinct) in PGR4, plus 31 out-of-function switch cases.
  - Instructions with no emitter are skipped, and the generator still exits 0.
  - Plain `dcbz` clears 32 bytes where Xenon clears 128.
  - FCTID/FCTIDZ is wrong at exactly 2^63.
- **Zero-config for new games:** this is the largest payoff. PGR4 needed 262 hand-written `functions` entries and about 6 passes. FM2 needs 28. Reading the `.pdata` EH flag, sizing from switch-table targets, and failing loudly would remove most of that. It is a large build, not a quick one.
- **Speed on weak CPUs:** the only items with real measured static gain are two. One is the indirect-call table displacement: about 2.6% smaller text in the file measured (about 0.5% of .text if extrapolated), and a few hundredths to under 1% runtime (estimate). The other is dropping `volatile` on guest accesses: -4% to -8% instructions in files compiled, with real hang risk. Both matter only on CPU-bound machines such as the FX-8350 and the 5800H iGPU. On GPU-CP-bound PCs (the 5800X) expect about 0%.
- **Decomp synergy:** dual-entry (native signature plus ctx shim) emission has the highest ceiling (microbench 2.8x per call, an upper bound). It is also an L-effort, high-risk project, and none of it is proven end to end.
- **Overall:** realistic whole-game speedup on a weak CPU is single-digit percent. Do not promise more.

## 2. Correctness bugs

### Confirmed

**C1. Branches that leave the function become `return;`**
- Where: `recompiler.cpp` `printFunctionCall` (~393-402) emits only `// ERROR <addr>`. Callers then print `return;`: plain `b` (~597-604), conditional branches (~409-420), and switch cases (~620-626).
- Repro:
  - FM2: `out/ppc_tu4/ppc_recomp.101.cpp:11607`, `sub_82771F08` `b 0x82773580`.
  - PGR4: 130 `// ERROR` lines (74 distinct) plus 31 `// ERROR: 0x..` switch cases.
- The FM2 auction crash came from the same mechanism: three XTS functions lost their shared epilogue, so r1 was never popped. It was worked around by hand-sized `functions` entries in `fm2_tu4.toml`.
- Fix:
  - Cheap, first: emit a loud no-return `ppc_unresolved_branch(0xADDR)`, or fail the generator.
  - Full: synthesize fragment entries or clone-inline the target blocks.
  - In `Analyse()` (~l.209), seed functions from `b`/`bc`/switch targets too, not only `bl`.
  - Do not let a config size override hide a `.pdata` start.
- Caveats: cap clone size, and handle fragments that branch back above their entry. SEH funclet regions interact with the parked locals work.

**C2. Unimplemented instructions are skipped silently**
- Where: `recompiler.cpp:2441` is `default: return false;`. Lines 2605-2608 print "Unrecognized instruction". The result of `Recompile(fn)` is discarded at ~2791, so the generator exits 0 with holes in the output.
- Fix: check the result and exit non-zero, or emit `ppc_unimplemented("mnemonic", addr)`. Add an opt-out flag for unreachable library code.
- Unhandled today (FM2 and PGR4 use none; checked by grep of the generated output):
  - About 91 of 239 vector mnemonics, for example vrlw, vpkuhum, vmax/vmin, vrfip.
  - About 35 scalar ones: lfdu, stfsu, lmw, addc, addme, mulhd, rldic, fctiw, fnmadd, mcrf, mtfsb0/1, the cr-logic ops.
- `vpkd3d128` handles only 3 of Xenia's 7 pack types, and the default hits `__builtin_debugtrap()` (l.2113, l.2391).
- `VCMPGTUB` and `VCMPGTUH` (l.1935-1941) lack the CR6 record-form update.

**C3. FCTID/FCTIDZ at exactly 2^63 returns 0x8000... instead of saturating**
- Where: `recompiler.cpp:914` and `:919` use `f64 > double(LLONG_MAX)`, and `double(LLONG_MAX)` is exactly 2^63.
- Repro (compiled):
  - Input 9223372036854775808.0 gives `8000000000000000`.
  - Input 9.3e18 gives `7fffffffffffffff`.
- Fix: change `>` to `>=` on both lines.
- FCTIWZ (l.924) is fine.
- Do not replace this with a "ppc_fctid" helper that uses `cvtt` for both forms. That would break FCTID's rounding.
- Affects 652 generated FM2 sites (639 FCTIDZ, 13 FCTID), and only for an input of exactly 2^63.

**C4. Plain `dcbz` clears 32 bytes**
- Where: `recompiler.cpp:828-833` uses `& ~31, 32`. DCBZL at 835-840 correctly uses 128. Xenia (`ppc_emit_memory.cc:1254-1260`) says plain dcbz always clears 128 on Xbox 360.
- FM2 has 2 plain sites:
  - `ppc_recomp.40.cpp:14855` sits in a loop with stride 128, so 96 of every 128 bytes stay stale.
  - `ppc_recomp.39.cpp:37061` is probably harmless.
- Fix: use `& ~127, 128`.
- The 25 `dcbzl` sites are already correct.
- Correction to one finding: no `dcbz128` decoder work is needed. It is already decoded as DCBZL.
- Nobody traced the consumer of the stale bytes, so the practical impact in FM2 is unknown.

**C5. The `blrl` debugtrap (and a stale `switch` width) in the FM2 output**
- The FM2 output is stale. It has a `__builtin_debugtrap()` for `blrl` at `ppc_recomp.102.cpp:9713`, in `sub_8277ACD0` (Live title-services code), and `switch (ctx.rN.u64)` at all 321 switch sites.
- ReXenon commit aa34d31 already fixes both. Regenerating with ReXenon picks them up.

### Plausible or latent

**C6. `stwcx`/`stdcx` is a value-compare CAS**
- Where: `recompiler.cpp:1210-1216`, `1703-1711`, `1064`, `1547`.
- It has no ABA protection and no reservation-address check.
- All 691 FM2 lwarx/stwcx pairs are same-function with identical (RA,RB), so no FM2 bug is shown.
- Make a Xenia-style scheme an opt-in config flag, default off. A per-granule generation table would still miss plain stores.

**C7. `sync`/`lwsync`/`eieio` emit nothing** (`recompiler.cpp:865, 1239, 1758`)
- The generated code has about 26 sites (sync 11, eieio 13, lwsync 2). I could not reproduce the counts, since nothing is emitted for them.
- The CAS already fences lwarx/stwcx. No real failing handshake was shown.
- This becomes mandatory if `volatile` is dropped (roadmap item 5). Use `mfence` for sync and a compiler barrier for the rest.

**C8. `mfocrf` hardcodes cr6; `mtfsf` ignores the FM field**
- `mfocrf` is at `recompiler.cpp:1285`; `mtfsf` is at `1312`.
- FM2 uses only FXM=0x02 and a full-mask `mtfsf`, so it is unaffected. These are silent miscompiles for other titles.
- Also hardcoded: BDNZF assumes the eq bit (ignores BI), and BDNZT handles only lt/gt/eq/so.

**C9. Many conditional branch forms are unhandled** (BEQCTR, BEQL, BSO/BNS and the like)
- The generic forms fall into the C2 `default` path. Replace the per-opcode cases with one BO/BI decoder.
- None appear in FM2 or PGR4.

**C10. `mftb` emits raw `__rdtsc()`** (`recompiler.cpp:1290`)
- The tick rate is wrong, and TBU is not shifted.
- FM2 post-patches with `tools/patch_mftb.py` on every configure (16 sites become `Fm2Timebase()`).
- Fix: a `PPC_MFTB` macro or a config `mftb_function`, with TBU as `>> 32`.
- Correction: arm64 does compile, because `__rdtsc` is already defined at `ppc_context.h:691-700`. Only the rate is wrong.

**C11. `mmioStore()` peeks `*(data+1)` without a bounds check** (`recompiler.cpp:366-370`)
- It normally reads the next function's first word. It is truly out of bounds only at the end of a section.
- `PPC_MM_*` are inert aliases today.
- A one-line bounds check fixes it.

**C12. Smaller FP semantics**
- VMX ops inherit the guest rounding mode, because RN goes into the shared host MXCSR.
- FNMADDS/FNMSUB flip NaN signs.
- `lfs` of a signalling NaN is quieted.
- FM2 has 3 CRT sites that set a non-nearest RN; none shown to affect vector code.
- Cosmetic unless a title needs NaN-exact behaviour.

**C13. Traps compile to nothing**
- `twi`/`tw*` are "no op" at `recompiler.cpp:1762-1780`.
- FM2 has 6,877 `twi 31,rN,22` assert idioms, 701 `twllei` and 192 `twlgei`.
- A log-once call for the TO=31 sites is nearly free. Do not make traps fatal by default, and keep the conditional forms debug-only.

**C14. Estimate instructions use exact division**
- `vrefp` (36 sites), `vrsqrtefp` (286) and `frsqrte` (3) use exact divide and sqrt instead of hardware table estimates.
- Xenia has console-read tables (BSD-3). Offer them as an opt-in `exact_estimates` flag. No divergence in FM2 has been shown.

## 3. Ranked roadmap

Format: what, where, expected gain (skeptic-corrected), risk, effort.

1. **Fail loudly everywhere (C1 cheap half and C2).**
   - Where: `recompiler.cpp` (default case ~2441, `Recompile` call ~2791, `printFunctionCall` ~402, switch default ~632).
   - Gain: no fps change. Missing pieces surface at generation time with a full list, instead of as hangs.
   - Risk: very low. Add an opt-out for dead library code.
   - Effort: S.

2. **Small exact fixes: C3, C4, MFOCRF/MTFSF decode, mmioStore bounds check, and regenerate FM2 so it picks up the `blrl`/u32-switch fixes.**
   - Gain: correctness only.
   - Risk: very low.
   - Effort: S.

3. **Indirect-call table displacement fits in int32.**
   - Where: `ppc_context.h:113` (`PPC_LOOKUP_FUNC`); move the table to about 0x843C0000 or higher (a config key `indirect_table_base`, plus a `static_assert`). The table fill is `loader.cpp:285`.
   - The displacement arithmetic is confirmed: the current one is -2,173,108,224, below INT32_MIN. A compiled snippet gives `call [rdx+2*rax-disp]`.
   - Measured on file 10 (researcher figures, not re-run): .text -2.6%, 687 bctrl sites, and `push r14` 107 down to 25 in that file.
   - Gain: extrapolated 22,473 sites x 5.9 B is about 130 KB, roughly 0.5% of .text. Runtime is estimated at a few hundredths to under 1%, and unmeasured.
   - Risk: very low.
     - The free range was checked: memory.cpp commits [0, 0xA0000000) and the guest heap is 0x40000000-0x7F000000.
     - `thread.cpp:276` and `wheel_ff.cpp:289` also use the macro and follow it automatically.
     - PGR4 needs its own base.
     - PGO profiles go stale.
   - Effort: S.

4. **Branches/switch targets inside other functions (C1 full) and zero-config function extents.**
   - Where: `Analyse()` in `recompiler.cpp`, and `XenonAnalyse`.
     - Seed from `b`/`bc`/switch targets.
     - Treat `.pdata` ExceptionFlag as an 8-byte EH header (replaces the 3 `invalid_instructions` values; 404 flagged FM2 functions).
     - Size non-pdata functions over their switch targets.
     - Use the `datafuncs.py` rule to seed data-pointer starts.
     - Add an `--emit-config` mode.
   - Gain: correctness and a large reduction in per-game config (FM2 28 entries, PGR4 262). Nothing for FM2 runtime.
   - Risk: medium. Clone-inline can bloat, data-pointer seeding has false positives, and funclet merging interacts with the parked locals item. Diff FM2 and PGR4 output before and after.
   - Effort: M (the C1 part) to L (full zero-config).

5. **Real barriers, then non-volatile guest loads/stores (plausible; gate on an A/B).**
   - Where: `ppc_context.h:37-87`.
     - Step 1: emit barriers for sync/lwsync/eieio/isync (S).
     - Step 2: make plain accesses non-volatile, keeping `volatile` for `PPC_MM_STORE_*` and lwarx/stwcx, and for loads inside call-free loops.
   - Measured:
     - File 101: instructions -4.1% to -4.8%, object size -4,378 B (reproduced).
     - File 50: -7.9% (claimed, not re-run).
     - sub_826214E8: 647 to 516 instructions (-20%).
   - Gain: estimated 1-4% of recompiled-code time on CPU-bound machines only, about 0% on a CP-bound PC.
   - Risk: medium-high, with silent hangs.
     - A non-volatile polling loop compiles to a bare `ret` (test).
     - Loops that write only ctx counters (`while (*flag==0 && --n)`) are poll loops too.
     - Switch-table loops are not covered by a backward-branch range scan.
     - Stores lose ordering, and the GPU-ring and XMA threads read guest memory.
   - Effort: M.
   - First step: measure one whole-TU build with `volatile` stripped, on the FX (ask the owner first), before building the loop analysis.

6. **Mode-neutral FP ops skip the MXCSR switch (lfd/stfd/fmr/fneg/fabs/fnabs/stfiwx/fcfid/fctiwz/fctidz only).**
   - Where: `printSetFlushMode` callers in `recompiler.cpp` (~888-1035, 1085-1117, 1571-1610).
   - Gain: small. The no-added-code subset is only about 111 unconditional sites plus their conditional checks.
   - Do not include `lfs`/`stfs` without measuring. They need extra slow-path code at about 52k sites that cancels most of the saving.
   - Add a throwaway counter in `setcsr` first to see whether `ldmxcsr` is hot.
   - Risk: low. Effort: S.

7. **Inline blr-only callees and the `__savegprlr`/`__restgprlr` thunks.**
   - Where: `recompiler.cpp:371-391`.
   - Counts:
     - `sub_82404EC0` is `blr` only and has 16,325 direct calls (about 9% of all direct calls).
     - About 11.5k save and 12.8k restore call sites (24.3k).
   - Part (a), eliding blr-only calls, is cheapest. Check hooks first (no hook on 82404EC0).
   - Gain: estimated 0-3% on FX/iGPU. The thunks also enable `non_argument_as_local`, because the save thunk reads `ctx.r12`. Code growth may eat some gain.
   - Risk: low, but it needs a hook list from config.
   - Effort: S for part (a), M for thunk inlining.

8. **r14-r31 (and r0/r11/r12) as locals.** Plausible, unmeasured, high risk.
   - Where: `non_volatile_as_local` (`recompiler.cpp:268-296`, `:391`) plus a new analysis.
   - Measured: sub_82263C28 581 to 527 instructions with `volatile` kept, but only 513 to 517 with `volatile` removed. The two wins overlap heavily.
   - Static data:
     - 109 of 50,530 functions read a callee-saved register before writing it (including sub_8242A6DC, sub_824328FC, sub_82773570).
     - 72 `bl` and 3 `b` sites from other functions land mid-function (funclet entries).
     - The two ideas for the blocker are a read-before-write dataflow pass, or a call-graph rule that flushes at funclet call sites. The call-graph rule is untested.
   - Unsolved gaps:
     - Writers such as setjmp/longjmp.
     - Indirect calls to unknown targets.
     - Hooks that read `ctx.r22-r31` (`perf_probe.cpp`).
     - The skipped save-slot stores.
   - Gain: estimated low single digits, CPU-bound machines only.
   - Risk: silent corruption; locals are zero-initialised.
   - Effort: L.
   - Only do it after item 5, and compare with a `ctx.r14-31` diff harness at every function exit.

9. **Runtime diagnostics.**
   - Where: `PPC_CALL_INDIRECT_FUNC` (`ppc_context.h:116`).
     - Fill every empty table slot with a `ppc_unmapped` stub. The fill has no runtime cost.
     - Update `GuestCall`'s null check, and keep the fill before the hooks.
   - FM2 already has `crash.cpp`, which logs guest LR and a host stack that names the calling function. What is missing is only the target address, so this is a convenience, not a fix for "undiagnosable" crashes.
   - Gain: debuggability only.
   - Risk: low. A `default: ppc_switch_miss(addr)` for switches is similar.
   - Effort: S.

10. **Build hygiene.**
    - Drop the 51k-line global extern header: 204 files each include it.
    - Measured: -fsyntax-only on a header-only file is 0.71 s (0.75 s in the recheck), of which about 0.5 s is `ppc_context.h`/simde/hooks. The externs cost only about 0.25 s per file.
    - Full-build saving is about 204 x 0.25 s = about 51 s of about 700 s CPU (about 7%), not the claimed 145 s. A PCH may get more.
    - The real benefit is incremental: address-bucketed chunking (today the split is `i % 256`) stops one added or removed function rewriting every later chunk and the header.
    - `genstubs.py` and `recomp.sh` still need an imports list.
    - Effort: S-M.

11. **Skeptic-downgraded, low priority.**
    - `ctx.lr` store elision:
      - Part (a), mtlr followed by blr (29.5k sites), is verified and safe as a peephole.
      - Part (b), callee never reads LR, is smaller than the 37-49k claimed. The linear scan is path-unsound, and hooks and imports read `ctx.lr` (for example `imports_mm.cpp:193` passes it to `WheelFfProcedure`).
      - Likely under 0.5% runtime.
    - Lifted-function production fast path (`lift.cpp` `LiftRun`):
      - Estimated 2-4 ns per call.
      - It is decomp-branch work, and dynamic call counts of the lifted set are not measured.
    - A single-MXCSR-mode option and the compile-time hot/cold `/order` file are speculative.
    - Dual-entry native-ABI emission (L, high risk): only a 20-50 function prototype should come before any commitment.

## 4. Refuted or already-resolved ideas (do not retry)

- **CR/CTR/XER dead-flag elimination.** Already locals. Asm shows fused cmp/jcc and no setcc.
- **Linker ICF.** `/opt:icf` saves about 0.5 KB.
- **`preserve_none` on `PPC_FUNC`.** File 10 grows 18.6%.
- **PGO and inlining of save/restore helpers.** Previously tried and parked (243 vs 250 fps, within noise). Item 7 is different work (recompile-time inlining, A/B on the FX), but expect little.
- **Indirect-call table lookup.** Already a direct index, one load. Direct calls are plain `call`, tail calls are `jmp`, and switches are jump tables. The only fix is the displacement (item 3).
- **MXCSR-hoist miscompile (clang moving an FP op above `ldmxcsr`).** Reproduced only in a contrived test. Two realistic patterns kept the correct order, and no site was found in `ppc_tu4`. Drop it unless new codegen keeps FP values in locals across a switch.
- **"dcbz128 is not decoded".** False. It is DCBZL, already handled with 128 bytes.
- **"`__rdtsc` blocks arm64".** False. An aarch64 definition exists.
- **mfocrf, OE-form, Rc-form and CA at 32 bits.** Same behaviour as Xenia, or zero FM2 sites (mfocrf is FXM=0x02 at all 15 FM2 sites).
- **The recompiler "is ahead of" upstream.** Upstream `hedge-dev/XenonRecomp` is still at ddd128b (our base). Of its 16 open PRs, none is a performance change.
  - #170: MFOCRF mask, mmioStore bounds.
  - #181: MULHD, BSO/BNS and so on.
  - #185: switch-aware block walker.
- **Moving liveness and ABI analysis from `livein.py` into the recompiler.** Rank last, and arguably do not do it.
  - `livein.py` parses the emitted C, so it cannot drift from the emission.
  - Its 21-bit register scope is deliberate.
  - It would tie the decomp branch to the recompiler it aims to remove.
  - Prefer a stable machine-readable annotation from the emitter if one is needed.
- **Native-link ABI tag per function.** Design only, no standalone gain. The one cheap piece is getting the hooked and taken set from config instead of grepping `src/`.
- **Swapping the GPL disassembler for a BSD decoder.** A legal and licensing task with no speed gain and an L-sized, medium-risk rewrite.
  - `ppc-dis.c` is GPL v2+ (binutils), and libmspack `lzxd.c` is LGPL 2.1.
  - The MIT licence covers upstream's own files; generated C++ is unaffected.
  - A cheaper step is a canonical BO/BI branch decoder.
- **Capping generated-file size for build wall time.** Roughly zero wall-clock gain on 16 cores: 716 CPU-s / 16 is about 45 s, which already exceeds the 25.6 s outlier. It would also hurt incremental stability.
- **Several "no gain" micro-ideas from the brief.** Do not re-propose them without new evidence: `-mmovbe`, ThinLTO, vector registers as locals, fsel/dpps tweaks.
- **Hardcoded claim "all 91 vector opcodes are missing".** Not an error per se. Most are unused by FM2 and PGR4. Add them on demand from the worklist item 1 produces.

## 5. MPC603e datasheet

It is a 32-bit G2 core with a 32-byte cache line, no VMX and no 64-bit instructions. It is not Xenon, and it does not apply to:

- the 128-byte line (the 32-byte `dcbz` bug likely descends from G2 assumptions),
- rld*/sld/srd/cntlzd/extsw/mulld/divd/fctid,
- VMX128,
- the Xenon timebase rate (49.875 MHz).

It is valid only for generic 32-bit semantics: rlwinm/rlwimi/srawi/cntlzw word behaviour, the mftb/mftbu TBL/TBU split, and the basic tw/twi trap condition encoding. For everything else use PowerPC ISA 2.02 Books I-III, the IBM Cell PPE docs, and Xenia's emitters (`D:\xenia-src\src\xenia\cpu\ppc`, hardware-verified comments).
